Guia de Uso ESJ V4 en GLPI

Sistema de administracion de proyectos de construccion para ESJ, enfocado en planeacion, naves, fases, actividades, RFIs y medicion de tiempos de ingenieria.

Contenido Objetivo Roles Flujo de negocio Uso paso a paso Reglas clave Correo SAP Tiempos

1. Objetivo del sistema

ESJ V4 convierte un correo de SAP en un proyecto operativo dentro de GLPI. Desde ese punto, el equipo puede planear naves, fases, fechas y paquetes de actividades; despues ejecutar el trabajo mediante tableros Kanban, tickets tipo RFI y reportes de tiempo.

En la version actual de prueba, el correo SAP se registra pegando el contenido en la Bandeja SAP. La logica de negocio es la misma que usara la integracion automatica por correo cuando se conecte el collector/IMAP.

2. Roles y responsabilidades

Rol / grupo Responsabilidad principal Que revisa en el sistema
Project Manager Seguimiento ejecutivo del proyecto. Resumen del proyecto, avance de fases, avance de actividades, bloqueos y estado general.
Lider de Ingenieria Asignar trabajo, revisar carga del equipo y liberar etapas. Kanban, responsables, actividades abiertas, RFIs bloqueantes y gate de construccion.
Planeacion Convertir el correo SAP en estructura operativa. Bandeja SAP, naves/edificios, fases, fechas y paquetes de actividades.
Diseno estructural Ejecutar y cerrar la etapa de diseno estructural. Actividades asignadas, estados del Kanban y RFIs relacionados.
Modelado de conexiones Ejecutar el modelo de conexiones y entregar planos finales completos. Actividades de modelado, pausas por RFI y cierre de la etapa core.
Planos de fabricacion / montaje Trabajar fases de construccion una vez liberado el gate. Fases activas, actividades por producto y tiempos de ejecucion.
Submittals / Requisiciones Gestionar entregables y solicitudes que requieren trazabilidad formal. Tickets vinculados al proyecto, fase, nave, actividad o producto.

El administrador de GLPI conserva acceso completo al sistema. Los usuarios operativos deben trabajar con el perfil ESJ Ingenieria.

3. Flujo de negocio

1 Correo SAP

Se recibe una notificacion de proyecto desde SAP con cliente, cotizacion, ubicacion y datos del suministro.

2 Bandeja SAP

El sistema registra el proyecto como pending_planning. Aun no hay fases listas para ejecutar.

3 Planeacion

Planeacion define naves/edificios, fases, fechas limite y paquetes de actividades precargadas.

4 Etapas core

Se trabajan Planeacion, Diseno estructural y Modelo de conexiones. Las fases de construccion permanecen bloqueadas.

5 Gate

Cuando las tres etapas core se cierran y no existen RFIs bloqueantes, el lider libera construccion.

6 Ejecucion paralela

Las fases de construccion se activan y pueden avanzar en paralelo por nave, fase, actividad y producto.

4. Uso paso a paso

4.1 Entrar al sistema

  1. Abrir GLPI en el navegador. En el ambiente local de prueba se usa http://localhost:8084.
  2. Iniciar sesion con un usuario asignado al perfil ESJ Ingenieria.
  3. Usar los accesos del sidebar: ESJ Inicio, ESJ Proyectos, Planeacion SAP, Kanban Ingenieria, RFIs y Bloqueos, Tiempos y SLA, Plantillas ESJ.

4.2 Registrar un proyecto desde SAP

  1. Entrar a Planeacion SAP.
  2. En Registrar correo SAP, pegar el contenido completo del correo. La pantalla de prueba ya trae un ejemplo precargado.
  3. Presionar Enviar a Planeacion.
  4. El sistema crea el proyecto y abre la pantalla para completar planeacion.

4.3 Completar planeacion

  1. Revisar los datos SAP: codigo, cliente, cotizacion y ubicacion.
  2. Definir las naves/edificios. Ejemplo: Nave A / Edificio A1.
  3. Activar solo las fases que aplican al proyecto.
  4. Asignar cada fase a una nave.
  5. Capturar fecha de inicio y termino limite por fase.
  6. Elegir el paquete de actividades: Sin plantilla, Ingenieria core, Productos de modelado, o Ingenieria core + modelado.
  7. Presionar Completar planeacion.

4.4 Revisar el proyecto

  1. Entrar a ESJ Proyectos y abrir el proyecto.
  2. Revisar metricas de avance de fases, avance de actividades y estado del gate de construccion.
  3. Desde el proyecto se puede ir a Kanban, RFIs y Tiempos.

4.5 Trabajar en Kanban

  1. Entrar a Kanban Ingenieria desde el proyecto.
  2. Las actividades aparecen agrupadas por estado.
  3. Usar Iniciar cuando comienza el trabajo operativo.
  4. Usar Pausa RFI cuando el trabajo queda detenido por una duda o bloqueo formal.
  5. Usar Reanudar cuando se resuelve la pausa.
  6. Usar Cerrar cuando la actividad esta terminada.

4.6 Registrar RFIs, restricciones, submittals o requisiciones

  1. Crear o identificar el ticket GLPI correspondiente.
  2. Entrar a RFIs y Bloqueos desde el proyecto.
  3. Vincular el ID del ticket.
  4. Seleccionar alcance: proyecto, fase, nave, actividad, tarea o producto.
  5. Seleccionar impacto: blocking si impide cerrar o avanzar; informational si solo documenta informacion.

5. Reglas clave de negocio

Trabajo tecnico comun Las actividades normales de ingenieria se gestionan como actividades/tareas del proyecto.
RFI y bloqueos RFIs, restricciones, submittals y requisiciones se manejan como tickets para conservar trazabilidad formal.
Fases bloqueadas al inicio Las fases de construccion no deben activarse hasta cerrar Planeacion, Diseno estructural y Modelo de conexiones.
Gate de construccion El gate solo libera fases si las tres etapas core estan cerradas y no hay RFIs bloqueantes abiertos.
Timers 24/7 Los tiempos se miden en calendario continuo, incluyendo noches, fines de semana y festivos.
Cierre bloqueado Una actividad o etapa no debe cerrarse si tiene RFIs bloqueantes pendientes.

7. Reportes de tiempo y toma de decisiones

El objetivo operativo del sistema es medir cuanto dura cada proceso para mejorar decisiones internas y futuras cotizaciones. Los eventos del sistema registran cambios de estado, inicios, pausas, reanudaciones y cierres.

Metrica Como se genera Para que sirve
Tiempo de planeacion Desde la recepcion del proyecto SAP hasta completar planeacion. Medir velocidad de arranque y detectar cuellos de botella iniciales.
Tiempo operativo de actividad Desde iniciar/reanudar hasta pausar/cerrar. Estimar capacidad real y tiempos por tipo de actividad o producto.
Tiempo pausado por RFI Desde Pausa RFI hasta Reanudar. Separar tiempo productivo de tiempo detenido por informacion faltante.
Duracion de fase Desde activacion hasta cierre de fase. Comparar desempeno entre fases, naves y proyectos.
Regla importante: no se depende de botones manuales de "timer". Los tiempos se calculan por eventos de negocio: crear, asignar, iniciar, pausar, reanudar, cerrar y liberar.

8. Criterios para validar un proyecto

  • El correo SAP crea un proyecto pendiente de planeacion.
  • Planeacion define al menos una nave y una fase activa.
  • Las fases de construccion quedan bloqueadas hasta cerrar las tres etapas core.
  • El Kanban muestra actividades por estado.
  • Un RFI bloqueante impide cerrar cuando aplica.
  • Los reportes de tiempos reflejan trabajo operativo y pausas RFI por separado.
  • El PM puede revisar resumen sin entrar al detalle tecnico de cada ticket.
